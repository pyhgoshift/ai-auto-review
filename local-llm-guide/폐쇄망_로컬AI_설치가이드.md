## 2. 왜 이 조합인가

### 2-1. MoE(전문가 혼합) 모델이 CPU 전용 PC에 유리한 이유
- 일반 모델: 26B 모델이면 글자 하나 만들 때 26B 전부 계산 → CPU에서 매우 느림
- MoE 모델: 26B 지식을 갖고 있지만 글자 하나에 **약 4B만 계산** → 4B 모델과 비슷한 속도, 더 넓은 지식
- 비유: 전문가 26명이 있는 사무실에서, 질문마다 **관련 전문가 4명만** 회의에 들어오는 방식

### 2-2. 메모리 32GB 배분 예시 (Gemma 4 26B-A4B 기준, 추정)
| 항목 | 사용량 |
|---|---|
| 윈도우 + 기본 프로그램 | 약 6~8GB |
| 모델 파일 | 약 14.4GB |
| 대화 기억 공간(문맥 16K 토큰) | 약 1~3GB |
| **여유** | **약 8GB 이상** |

### 2-3. 실행 프로그램 비교
| 방식 | 장점 | 단점 | 공공기관 적합도 |
|---|---|---|---|
| **llama.cpp (추천)** | 오픈소스(MIT), 설치 불필요, 원격 전송 기능 없음, 채팅 화면 내장 | 명령어 한 줄로 실행해야 함 (배치 파일로 해결) | 높음 |
| LM Studio | 가장 쉬운 화면 | 비공개 소프트웨어, 업데이트 확인 기능 끄기 필요, 기관 사용 약관 확인 필요 | 중간 |
| Ollama | 오픈소스, 설치형 | 백그라운드 서비스 상주, GGUF 등록 절차 필요 | 중간 |

## 3. 설치 방법

### 3-1. 인터넷 PC에서 준비 (반입 파일 만들기)

1. **llama.cpp 윈도우 CPU 버전 다운로드**
   - 주소: `https://github.com/ggml-org/llama.cpp/releases`
   - 최신 릴리스의 Assets에서 이름이 **`llama-b<번호>-bin-win-cpu-x64.zip`** 형태인 파일
   - Gemma 4를 지원하는 **2026년 하반기 이후 빌드**를 받을 것
2. **모델 파일 다운로드**
   - 주소: `https://huggingface.co/google/gemma-4-26B-A4B-it-qat-q4_0-gguf`
   - 파일: **`gemma-4-26B_q4_0-it.gguf`** (14,439,363,584 바이트)
3. **(선택) 경량 대안 모델**
   - 주소: `https://huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-4GB`
   - 파일: `Nemotron-3.5-Bolt-E4B-Q4_K_M.gguf` (6,180,446,208 바이트)
4. **(대비용) Microsoft Visual C++ 재배포 패키지(x64)**: 실행 시 `VCRUNTIME140.dll` 오류가 날 경우 대비
5. **체크섬 확인** (PowerShell)
   ```powershell
   Get-FileHash .\gemma-4-26B_q4_0-it.gguf -Algorithm SHA256
   ```
   | 파일 | 공식 SHA256 |
   |---|---|
   | gemma-4-26B_q4_0-it.gguf | `3eca3b8f6d7baf218a7dd6bba5fb59a56ee25fe2d567b6f5f589b4f697eca51d` |
   | Nemotron-3.5-Bolt-E4B-Q4_K_M.gguf | `c8af2b8aea10a690a1d9491db744a9446660173cb38fc489612b556615a69612` |

   위 값은 2026-11-18에 Hugging Face 공식 저장소에서 받은 파일로 직접 대조해 확인했습니다.
6. 기관 절차에 따라 **승인된 매체로 반입** (악성코드 검사, 반입 대장 기록)

### 3-2. 폐쇄망 PC에서 설치

1. 폴더 만들기
   ```
   C:\LocalAI\llama\     ← llama.cpp 압축 해제
   C:\LocalAI\models\    ← .gguf 모델 파일
   ```
2. 반입 후 **체크섬을 한 번 더** 확인 (3-1의 5번과 같은 값이어야 함)
3. `C:\LocalAI\start.bat` 파일 만들기 (메모장으로 작성, 인코딩은 ANSI 또는 UTF-8)
   ```bat
   @echo off
   cd /d C:\LocalAI\llama
   llama-server.exe ^
     -m C:\LocalAI\models\gemma-4-26B_q4_0-it.gguf ^
     --host 127.0.0.1 --port 8080 ^
     -c 16384 -t 6 --jinja
   pause
   ```
   - `--host 127.0.0.1`: **내 PC에서만** 접속 가능 (절대 `0.0.0.0`으로 바꾸지 말 것)
   - `-c 16384`: 한 번에 다룰 수 있는 글자 양(약 A4 15~20쪽). 메모리가 부족하면 `8192`로 줄임
   - `-t 6`: CPU **물리 코어 수**로 설정 (작업 관리자 > 성능 > CPU > "코어" 숫자)
4. `start.bat` 더블클릭 → 검은 창에 `server is listening on http://127.0.0.1:8080` 표시 확인
5. 브라우저에서 **`http://127.0.0.1:8080`** 접속 → 채팅 화면 사용
6. 윈도우 방화벽 허용 창이 뜨면 **허용하지 않아도 됩니다** (내 PC 안에서만 쓰므로)

### 3-3. 종료
- 검은 창을 닫으면 종료됩니다. 메모리도 바로 반환됩니다.

## 5. 설치 후 반드시 할 시험 (수용 기준)

아래 6개를 넣어 보고, **사람이 정답과 비교**하십시오.

1. 민원 요약: 실제와 비슷한 가상 민원 1건 → 3줄 요약
2. 분류(JSON): `{"담당": "...", "긴급도": 1~5, "사업주비협조": true/false}`
3. 공문 초안: 날짜를 주고 형식대로 작성 → **연도·요일을 지어내지 않는지**
4. 사실 확인: "모르면 모른다고 답하라"를 붙여 업무 규정 질문
5. 계산: 증가율 계산
6. 표준화 개념: '재해일자' 정리

| 판정 | 기준 |
|---|---|
| 도입 가능 | 6개 중 5개 이상 정확, 날짜·숫자를 지어내지 않음 |
| 조건부 | 4개 정확 → 요약·문장 다듬기 용도로만 |
| 부적합 | 3개 이하 |

## 6. 업무에 쓰는 요령

### 6-1. 매번 앞에 붙일 기본 지시문 (채팅 화면 설정의 "시스템 프롬프트"에 저장)
```
너는 공공기관 업무 보조자다.
- 내가 준 자료에 있는 내용만 근거로 답한다.
- 날짜, 금액, 법령, 기준은 자료에 없으면 지어내지 말고 "확인 필요"라고 쓴다.
- 모르면 모른다고 말한다.
- 결과는 초안이며 담당자가 검토한다는 전제로 작성한다.
```

### 6-2. 잘 맞는 일 / 맡기면 안 되는 일
| ✅ 맡겨도 되는 일 (사람 검토 전제) | ❌ 맡기면 안 되는 일 |
|---|---|
| 회의록·민원 요약 | 민원 자동 분류 후 자동 배정 |
| 공문·보고서 형식 잡기, 문장 다듬기 | 법령·지급 기준 안내 |
| 표 정리, 항목 뽑기 | 날짜·금액이 들어간 문서의 무검토 발송 |
| 아이디어 정리 | 개인에 대한 판단 (예: 사업주 비협조 여부) |

### 6-3. 지어내기를 줄이는 방법
- 공문 서식, 관련 규정 문단을 **함께 붙여 넣고** "이 자료만 근거로" 요청
- 긴 문서는 **나눠서** 넣기 (문맥 설정 `-c` 범위 안에서)

## 8. 문제 해결

| 증상 | 해결 |
|---|---|
| `VCRUNTIME140.dll`이 없다는 오류 | 반입해 둔 Visual C++ 재배포 패키지 설치 |
| 창이 바로 닫힘 | `start.bat` 마지막 `pause`로 오류 메시지 확인. 경로 오타 확인 |
| `unknown model architecture` 오류 | llama.cpp가 너무 옛날 버전 → 최신 빌드로 교체 |
| 메모리 부족·멈춤 | `-c 16384` → `8192`로 줄이기. 다른 프로그램 종료. 그래도 안 되면 경량 대안(Nemotron) 사용 |
| 너무 느림 | `-t` 값을 물리 코어 수로 맞추기. 노트북이면 전원 어댑터 연결 + 고성능 모드 |
| 한국어 답이 이상함 | 기본 지시문(6-1)에 "한국어로 답하라" 추가 |
