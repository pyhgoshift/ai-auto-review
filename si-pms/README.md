# SI-PMS: SI 프로젝트 투입 인력·PC·보안 통합 관리

인력이 들어오면 **한 번만 입력**하고, 그 데이터로 인력 투입 대장, PC·자산 대장, 보안서약·교육 대장, 계정 대장, 철수 확인서를 **HWP(HWPX)·엑셀(CSV)로 바로 출력**하는 시스템입니다.
고객사 **폐쇄망**에 반입할 수 있도록 **실행파일 1개 + 데이터 파일 1개(SQLite)**로 동작하며, 인터넷·DB 서버·런타임 설치가 필요 없습니다.

## 0. QR 기반 완전 자동화 (PMO 1인 운영)

```
[현장 QR] ─스캔→ 본인 등록(정보 + 반입 노트북 MAC/시리얼 + 동의·서약·교육 서명)
                   │ 자동: 등록코드 검증·MAC 형식/중복 검사·허용 소속사 확인·반입장비 자동 등록
                   ▼
[대시보드 승인 대기열] 자동 점검 결과 표시 → PMO "승인" 1클릭(점검 통과 건은 일괄 승인)
                   │ 자동: IP 대역에서 빈 IP 배정 + NAC 등록 요청 생성
                   ▼
[IP·NAC] 등록 CSV·신청서 HWP 자동 생성 → NAC 담당 전달 → PMO "완료 처리" 1클릭
                   │ 자동: 본인 상태 페이지에 IP/서브넷/게이트웨이/DNS 공개 (등록 전엔 비공개 = 게이트)
                   ▼
[철수예정일 경과] 자동: 철수 진행 전환, 반입장비 반출 처리, NAC 해제 요청
                   │ PMO: 해제 파일 전달 후 "해제 완료" 1클릭 → IP 자동 회수·재사용
                   ▼
[매일 자동] 제출 패키지 ZIP(대장 5종 HWP+CSV, NAC 등록/해제 신청서, IP 사용현황) → data/outbox/
```

PMO가 직접 하는 일은 **① 승인 클릭 ② NAC 파일 전달 후 완료 클릭 ③ 회사 지급 PC 실물 반납 기록** 세 가지뿐입니다.

### 설정 순서 (최초 1회)
1. 설정 → **접속 주소**, **IP 대역**(예: `10.0.1.10-10.0.1.200`), 서브넷/게이트웨이/DNS, **등록 허용 소속사**
2. 서약·교육 → 고객사 문구로 교체
3. 등록 QR → 인쇄해서 출입구·자리에 부착 (유출 의심 시 "등록코드 재발급")

### ⚠ 반드시 먼저 확인할 것: 휴대폰이 이 서버에 닿는가
폐쇄망 서버는 보통 **LTE 휴대폰에서 접속되지 않습니다.** 다음 중 하나가 필요합니다.
- **(권장) NAC 격리망/등록 VLAN에서 이 서버만 허용**: 미등록 노트북을 랜에 꽂으면 NAC가 등록 페이지로 보내는데, 그 대상을 이 시스템(`/join?c=...`)으로 지정합니다. QR 대신 노트북 브라우저로 등록하게 됩니다. 이 경우가 "등록하지 않으면 네트워크를 못 쓴다"를 가장 강하게 보장합니다.
- 현장 등록용 Wi-Fi(이 서버만 접근 가능한 SSID)에 휴대폰을 연결해 QR 접속
- 입구에 등록용 태블릿/PC(키오스크) 비치
- 고객사가 허용하면 DMZ에 등록 서버를 두고 내부망과 DB 파일을 주기 반입

## 1. 업무 흐름

```
PMO: 투입 요청 등록 ──▶ 개인 링크 발급 ──▶ (메신저/메일로 전달)
                                              │
투입 인력: 링크 접속 → 본인 정보 입력 → 개인정보 동의 → 보안서약 → 보안교육 확인 → 성명 서명
                                              │
PMO: 승인 ──▶ PC 지급·보안 점검 ──▶ 계정 발급 기록 ──▶ (투입 중: 정기교육 만료·점검 누락 알림)
                                              │
PMO: 철수 시작 ──▶ 체크리스트(자산 반납·계정 회수·출입증·철수서약) ──▶ 철수 완료 ──▶ 보관기간 후 개인정보 파기
```

| 상태 | 의미 |
|---|---|
| 투입요청 | PMO가 등록, 본인 입력 전 |
| 승인대기 | 본인이 입력·서명 완료 |
| 투입중 | 승인 완료 |
| 철수진행 | 철수 체크리스트 진행 중 |
| 철수완료 | 모든 회수 완료(완료 전에는 버튼이 잠김) |

**대시보드의 "지금 챙겨야 할 일"**은 감사에서 자주 지적되는 누락을 자동으로 찾아 보여줍니다. 승인 대기, 서약·교육 미이행·만료(30일 전 예고), PC 미지급, 보안 점검 미실시·부적합·30일 경과, 철수 예정 14일 전, 철수 미회수 항목, 개인정보 보관기간 경과가 대상입니다.

## 2. 실행

```bash
# 빌드 (인터넷 되는 PC에서. 폐쇄망 서버 OS에 맞춰 교차 컴파일)
GOOS=windows GOARCH=amd64 go build -o si-pms.exe .
GOOS=linux   GOARCH=amd64 go build -o si-pms .

# 실행
./si-pms -addr :8080 -data ./data
# HTTPS (권장): ./si-pms -addr :8443 -data ./data -cert server.crt -key server.key
```

처음 실행하면 콘솔에 `admin` 계정의 임시 비밀번호가 출력됩니다. 첫 로그인 때 비밀번호를 변경해야 합니다.
이후 **설정** 화면에서 프로젝트명, 고객사, PC 점검 항목, 계정 대상 시스템을 고객사 기준으로 바꾸세요.
**서약·교육** 화면에서는 기본으로 들어 있는 서약서·동의서·교육자료 초안을 고객사 문구로 교체하세요.

**반입물**: `si-pms(.exe)` 파일 1개. 데이터는 `data/` 폴더에 생깁니다(`pms.db`, 업로드 양식, 백업).

## 3. 대장 출력과 고객사 양식

- **대장 출력** 화면: 인력, PC·자산, 보안서약, 보안교육, 계정 대장을 HWP 또는 CSV로 받습니다.
- **개인별 문서**: 인력 상세 화면에서 서명한 서약서를 HWP로, 철수 확인서를 HWP로 받습니다.
- **고객사 양식으로 바꾸기**
  1. 고객사 한글 양식을 엽니다(또는 "양식 받기"로 받은 기본 양식을 고칩니다).
  2. 값이 들어갈 자리에 `{{성명}}`, 표의 반복 행에는 `{{인력.성명}}`처럼 입력합니다. 화면에 자리표시자 전체 목록이 있습니다.
  3. **다른 이름으로 저장 → HWPX**로 저장해 업로드합니다. 고객사가 .hwp를 요구하면 출력물을 한글에서 열어 HWP로 다시 저장하세요.

## 4. 보안 설계

| 항목 | 구현 |
|---|---|
| 관리자 인증 | PBKDF2-SHA256(21만 회) 비밀번호, 10자 이상·3종 조합, 5회 실패 시 10분 잠금, 첫 로그인 시 변경 강제 |
| 권한 | 관리자(PMO) / 조회전용(고객사 보안담당 등) |
| 세션·요청 | HttpOnly·SameSite 쿠키, 모든 POST에 CSRF 토큰과 출처(Origin) 검사, CSP 등 보안 헤더 |
| 본인 링크 | 추측 불가능한 무작위 토큰. DB에는 해시만 저장하고 유효기간을 둠. 승인·철수 완료 시 폐기, 재발급하면 이전 링크 무효 |
| 서명 증빙 | 서명 시점의 문서 본문 전문, 버전, SHA-256 해시, 서명 성명, 시각, IP를 보관 |
| 감사 추적 | 로그인, 등록, 승인, 지급, 출력, 파기 등 모든 변경과 출력을 감사 로그에 기록 |
| 개인정보 최소화 | 철수 후 보관기간이 지나면 알림이 뜨고, 버튼 하나로 연락처·이메일·생년월일을 파기(성명·이력·서명은 증빙으로 보존) |
| 출력 안전 | CSV 수식 주입 방지, HWPX 값 XML 이스케이프 |

## 5. 알려진 한계와 운영 시 주의

- **전자서명은 "성명 입력 + 동의 체크" 방식**입니다. 공인 전자서명이 아니므로 고객사가 자필 서명을 요구하면, 출력한 서약서에 자필 서명을 받고 "서면/집합" 기록 기능을 함께 쓰세요.
- **HWPX 출력물은 자동 검증(구조 검사, python-hwpx 파서)만 거쳤습니다.** 실제 고객사 한글 버전에서 열리는지 반드시 먼저 확인하세요.
- 양식 행 복제는 **병합되지 않은 일반 행**에서만 동작합니다.
- DB 파일 자체는 암호화하지 않습니다. 서버 디스크 접근 통제와 백업 파일 반출 절차로 보호하세요.
- 메일·메신저 자동 발송 기능은 없습니다. 본인은 QR 등록 후 받은 상태 페이지(같은 휴대폰에서 QR 재스캔 시 자동 이동)로 진행 상황과 IP를 확인합니다.
- NAC 연동은 **파일(CSV)·신청서 전달 방식**입니다. NAC 제품이 API를 열어 주면 `nac.go`의 완료 처리 지점에 어댑터를 붙여 완전 무인화할 수 있습니다.
- MAC은 본인 입력값입니다. 형식·중복은 자동 검사하지만 실제 장비와 일치하는지는 NAC 인증 단계에서 확인됩니다(틀리면 접속 불가 → 본인이 PMO에 문의).
- IP 게이트는 "시스템이 IP를 알려주지 않는다"는 것이며, 실제 차단은 NAC가 합니다. NAC에 미등록 MAC 차단 정책이 켜져 있어야 의미가 있습니다.
- 실제 계정 생성이나 PC 보안 에이전트 점검은 각 시스템에서 수행하고, 여기에는 사실과 결과만 기록합니다.

## 6. 개발

```bash
go test ./...                     # 전체 생애주기, 권한, CSRF, 잠금, HWPX 엔진 테스트
python tools/gen_templates.py     # 기본 HWPX 양식 재생성 (pip install python-hwpx 필요, 운영에는 불필요)
```

| 파일 | 역할 |
|---|---|
| `model.go` | 상태 흐름, 미이행 판정, 철수 체크리스트, 승인 자동 점검, 알림 규칙 |
| `join.go` | QR 셀프 등록, 등록 QR 포스터, 요청 횟수 제한 |
| `nac.go` | MAC 검증, IP 대역 자동 배정·회수, NAC 등록/해제 요청과 파일 출력 |
| `scheduler.go` | 매일 자동 작업(철수예정일 경과 처리, 제출 패키지 생성) |
| `people.go` `assets.go` `docs.go` `selfsvc.go` | 화면별 처리 |
| `hwpxfill.go` | HWPX 양식 채우기 엔진(자리표시자, 행 복제, 쪼개진 run 병합) |
| `export.go` | 대장 데이터 구성, HWPX/CSV 출력, 양식 업로드 |
| `auth.go` `settings.go` | 인증·세션, 설정, 사용자, 감사 로그, 백업 |
