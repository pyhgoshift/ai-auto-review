# 기능 점검 및 실제 적용 테스트 결과

- 점검일: 2026-10-24
- 대상: `si-pms` (Go 소스 19개 파일, 테스트 포함 약 6,300줄)
- 방법
  1. **코드 전수 조사**: 화면·기능(라우트) 69개, 화면 파일 20개, 설정 19개 항목의 사용처 확인, Go 공식 도구(`deadcode`)로 호출되지 않는 코드 탐지
  2. **자동 테스트**: 단위·통합 테스트 21개(하위 시나리오 포함 23개), 동시성 검사(`-race`)
  3. **실제 적용 테스트(UAT)**: 가상 프로젝트를 브라우저로 처음부터 끝까지 운영하며 53개 항목 확인(`tools/uat/uat.py`)

| 고객사 폐쇄망 | 실행파일 1개 + SQLite, 외부 통신 없음 | 완료 | 빌드 확인 |
| PMO 1명으로 운영(완전 자동화) | 일괄 승인, 자동 철수·자동 완료, NAC 만료일, 만료일 변경 자동 감지, 제출 패키지·백업 자동 | 완료 | UAT 7·14·15·16 |
| 한국어 구성 | 화면·메시지·감사 로그·출력물·자동 작업·서버 로그·실행 옵션 | 완료 | UAT 19, 자동 테스트 |

## 2. 기능별 점검과 필요성 판단

| 기능 | 하는 일 | 판단 |
|---|---|---|
| QR 셀프 등록 / 내 상태 화면 | 투입 인력이 직접 등록·서명, 진행 상태·IP 확인, 철수서약 | **핵심** |
| 승인 대기열(자동 점검·일괄 승인) | 서약·날짜·소속사·MAC·IP 여유를 자동 점검 후 한 번에 승인 | **핵심** |
| IP 자동 배정·회수 | 대역에서 빈 IP 배정, 예약 주소 제외, 해제 시 회수 | **핵심** |
| IP·NAC(등록·만료일 변경·해제) | NAC 담당 전달용 CSV·HWP, 완료 처리 | **핵심** |
| PC·자산, 보안 점검 | 지급 PC 대장, 점검 기록·알림 | **핵심** |
| 서약·교육 문서 관리 | 문구 교체, 재서명 버전, 유효기간, 집합 교육 일괄 기록 | **핵심** |
| 대장 출력·고객사 양식·제출 패키지 | 제출 서류 자동화 | **핵심** |
| 철수 체크리스트·자동 철수·자동 완료 | 철수 누락 방지 | **핵심** |
| 자동 작업 화면 | 자동 처리의 결과·실패 확인 | **필요**(무인 운영의 감시 수단) |
| 감사 로그 | 누가 무엇을 했는지 증빙 | **필요**(보안 감사) |
| 조회전용 계정 | 고객사 보안담당 직접 확인 | **필요**(PMO 응대 부담 감소) |
| 백업(자동·수동) | 데이터 보호 | **필요** |
| 개인정보 파기 | 보관기간 경과 후 연락처 등 삭제 | **필요**(개인정보보호법) |
| 계정 발급·회수 기록 | VPN·Git 등 계정 대장, 철수 체크리스트 항목 | **필요**(계정 대장을 요구하지 않는 고객사라면 기록하지 않아도 됨) |
| 출입증 번호·반납 | 철수 체크리스트 항목 | **선택**(번호를 입력하지 않으면 체크리스트에서 자동 통과) |
| 대리 등록 + 개인 링크 | QR 등록이 불가능한 사람을 PMO가 대신 등록 | **조정함**: 기존 "투입 요청 등록"을 "대리 등록(QR 불가 시)"으로 바꾸고 예외 경로임을 안내 |
| 대시보드 "다가오는 투입·철수(30일)" | 30일 내 일정 표 | **중복 후보**: 철수 14일 전 알림과 일부 겹침 |
| 대시보드 "소속사별 투입 인원" | 소속사별 인원 수 | **부가 정보**: 유지 비용이 없어 남겨 둠 |

### 쓸데없이 만들어진 것

- **호출되지 않는 코드 1개(`ipPool.size`)를 찾아 삭제**했습니다. 그 외 화면·기능 69개, 화면 파일 20개, 설정 19개 항목은 모두 실제로 쓰이고 있습니다.
- **기능 단위의 불필요한 기능은 없었습니다.** 다만 아래 두 가지는 운영해 보고 판단할 수 있습니다.
  - 대시보드 "다가오는 투입·철수(30일)" 카드: 알림과 일부 겹칩니다. 빼도 업무에 지장은 없습니다.
  - 대리 등록 경로: QR 등록이 현장에서 잘 되면 거의 쓰지 않게 됩니다. 휴대폰 접속이 안 되는 상황의 대비책이라 남겨 두었습니다.

## 3. 실제 적용 테스트(UAT) 결과: 53/53 통과

가상 프로젝트 "OO공단 차세대 시스템 구축"(PMO 1명, 투입 인력 5명 + 대리 등록 1명)을 브라우저로 운영했습니다.

| 단계 | 확인 항목 | 결과 |
|---|---|---|
| 1. 첫 로그인 | 임시 비밀번호 → 변경 강제, 약한 비밀번호 거절, PMO 실명 설정 | 통과 |
| 2. 초기 설정 | 저장, 잘못된 게이트웨이 입력 시 전체 미저장 | 통과 |
| 3~5. 준비 | 기본 문서 4종, PC 3대 CSV 일괄 등록과 MAC 표준화, QR 포스터 | 통과 |
| 6. QR 등록 | 4명 등록, MAC 중복 거절, MAC 다른 표기 허용, 지난 철수예정일 거절, 같은 사람 중복 거절, 허용되지 않은 소속사 거절, 잘못된 등록코드 거절 | 통과 |
| 7. 승인 | 승인 대기 4명, 일괄 승인 | 통과 |
| 8. 게이트 | NAC 등록 전 본인 화면에 IP 비공개 | 통과 |
| 9~10. 배정 | 지급 PC 배정, 예약(.0~.9) 제외하고 .10부터 배정, 등록 대기 4건 | 통과 |
| 11. NAC | 고객사 양식 머리글 CSV, 만료일시·MAC 표기, 신청서 HWP, 완료 처리 | 통과 |
| 12. 본인 확인 | QR 재스캔 → 상태 화면, IP·게이트웨이·DNS 공개 | 통과 |
| 13. 점검·계정 | 보안 점검 4대, 계정 발급 | 통과 |
| 14. 연장 | 철수예정일 변경 → 대시보드 알림, 변경 CSV, 완료 처리 | 통과 |
| 15. 조기 철수 | 철수 시작, 본인 화면 철수서약, NAC 해제, 체크리스트 충족 시 자동 완료 | 통과 |
| 16. 자동 철수 | 철수예정일 경과 → 자동 철수 진행, NAC 해제 요청 자동 생성 | 통과 |
| 17. 출력 | 대장 5종 HWP·CSV, 철수확인서·서약서, 제출 패키지, 엑셀 BOM, 대장에 PMO 실명 | 통과 |
| 18. 조회전용 | 조회 가능, 등록 버튼 숨김, 설정 접근 차단 | 통과 |
| 19. 관리 | 감사 로그 한국어 검색, 백업, 개인정보 파기, 대리 등록 → 서면 이행 → 승인 | 통과 |
| 20. 최종 | 대시보드 | 통과 |

출력물 8종(대장 5종, NAC 신청서, 서약서, 철수확인서)은 독립 구현인 python-hwpx로 열어 **규격 오류 0건, 남은 자리표시자 0건**을 확인했습니다.

## 4. 이번 점검에서 발견해 고친 결함

| # | 결함 | 영향 | 조치 |
|---|---|---|---|
| 1 | 철수예정일이 이미 지난 사람이 승인되고 NAC 등록 요청이 나감 | 만료된 NAC 등록 신청, 대장 오류 | QR 등록 시 거절, 승인 점검 항목 추가, 승인 차단 |
| 2 | PMO 이름을 바꿀 화면이 없어 출력물 작성자·승인자가 모두 "관리자" | 제출 서류에 실명 누락 | "내 정보"에서 이름 변경 |
| 3 | 모바일 QR 등록 화면의 PC 선택지 문구가 글자 단위로 흩어짐 | 투입 인력 혼란 | 선택지 레이아웃 수정 |
| 4 | 대장 출력 화면에서 NAC 신청서 위치를 "인력 상세"로 잘못 안내 | PMO 혼란 | "IP·NAC 화면"으로 수정 |
| 5 | 호출되지 않는 함수 | 없음(정리) | 삭제 |

1·2번은 회귀 테스트(`TestPastEndDateBlocked`, `TestProfileNameUsedInExports`)를 추가했습니다.

## 5. 아직 확인하지 못한 것 (현장 적용 전 필수)

| 항목 | 이유 | 확인 방법 |
|---|---|---|
| **HWPX가 고객사 한글에서 열리는지** | 개발 환경에 한글 프로그램이 없음 | 제출 패키지 ZIP을 고객사 PC 한글에서 열기 |
| **휴대폰이 서버에 접속되는지** | 폐쇄망 구성에 따라 다름 | 현장에서 QR 접속 시험. 안 되면 매뉴얼 8장의 대안 |
| **NAC 가져오기 양식·만료일 지원·차단 정책** | 고객사 NAC 제품마다 다름 | NAC 담당에게 양식을 받아 설정의 열 구성 맞춤 |
| 대규모 인원 성능 | 테스트는 수십 명 규모 | 수백 명 이하는 문제 없을 것으로 예상(단일 SQLite) |
| 전자서명의 법적 효력 | 성명 입력 방식(공인 전자서명 아님) | 고객사가 자필 서명을 요구하면 서면 기록 병행 |

## 6. 다시 점검하는 방법

```bash
cd si-pms
go vet ./... && go test ./...              # 자동 테스트
go test -race ./...                        # 동시성 검사(CGO 필요)

# 실제 적용 테스트(개발 PC, Playwright 필요)
./si-pms -addr 127.0.0.1:18091 -data uat-data > uat-server.log &
SI_PMS_URL=http://127.0.0.1:18091 SI_PMS_LOG=uat-server.log python tools/uat/uat.py
```
