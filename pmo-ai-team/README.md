# PMO 주간보고 AI 팀 (첫 번째 에이전트 팀)

> 대상: 공공기관 IT 사업 PMO · 코드를 조금 읽을 수 있음 · 주 5시간 이상
> 금지: 외부 발송·게시 / 업무·기관 자료를 클라우드 AI에 입력 / 결제·구독 / 투자 판단
> 실행 위치: **폐쇄망 PC의 로컬 AI** (`../local-llm-guide/폐쇄망_로컬AI_설치가이드.md`)

---

## 1. 사용 사례: 왜 "주간보고 초안"인가

| 후보 | 이번 달 절약 | 판단 |
|---|---|---|
| **주간보고 초안 작성** | 매주 반복, 서식이 정해져 있고, 원자료(수행사 보고·회의 메모·이슈대장)가 이미 있음 | **✅ 1순위** |
| 회의록 정리 | 효과 큼. 주간보고 팀의 "정리 담당"을 그대로 재사용 가능 | 2주 차에 추가 |
| 산출물 검토 (기준표 대조) | 효과 크지만 문서가 길어 로컬 모델 문맥 한계에 걸림 | 3~4주 차 |
| 이메일·후속 연락 | 외부 발송 금지 원칙과 충돌 | 보류 |
| 잠재고객·고객 응대 | PMO 업무와 무관 | 해당 없음 |
| 기술 소식 검증 | 업무 자료가 필요 없어 클라우드 Claude로 충분 (지금 하는 방식) | 팀 불필요 |

**핵심 원칙:** 업무 자료는 클라우드에 넣지 않습니다. 그래서 팀은 **폐쇄망 PC의 로컬 AI**에서 돌고, Claude(인터넷 쪽)는 **가상 자료로 설계·시험만** 합니다.

## 2. 팀 지도

```
                     [나: PMO 담당자]
                           ↑  (검토 요청서만 받음, 결재는 내가)
                    ⓪ 코디네이터
                           ↑
 원자료 ─▶ ① 정리 담당 ─▶ ② 작성 담당 ⇄ ③ 검토 담당
 (붙여넣기)   JSON으로        서식대로       사실 대조
              옮겨 적기       문장 작성      통과/반려
                                  ↑            │
                                  └─ 반려(최대 2회) ┘
```

| 에이전트 | 단 하나의 책임 | 절대 하지 않는 일 | 받는 것 | 내놓는 것 | 넘기는 곳 |
|---|---|---|---|---|---|
| ⓪ 코디네이터 | 사람에게 줄 **검토 요청서** 작성 | 본문 수정, 발송·게시, 새 사실 | 최종초안, 검토이력, 정리JSON | 세 줄 요약 + 확인할 것 + 승인 요청 | 나 |
| ① 정리 담당 | 원자료 → **JSON**으로 옮겨 적기 | 해석, 계산, 문장 작성 | 원자료, 기준일 | 정리JSON (모르는 값은 null + 확인필요) | ② |
| ② 작성 담당 | JSON → **서식대로 문장** | 원자료 재해석, 새 숫자·날짜 | 정리JSON, 서식, 반려사항 | 보고서 초안 | ③ |
| ③ 검토 담당 | 초안 ↔ JSON **사실 대조** | 직접 고쳐 쓰기, 문체 지적 | 정리JSON, 초안 | 통과/반려 + 문제 목록 | 반려면 ②, 통과면 ⓪ |

**겹치지 않게 하는 장치:** 모든 에이전트가 **같은 정리JSON 하나를 "사실의 기준"**으로 씁니다. ①만 원자료를 읽고, ②는 JSON만 보고 쓰고, ③은 JSON과만 대조합니다. 그래서 누가 무엇을 바꿨는지 추적됩니다.

**"잘된 일"의 정의**
| 에이전트 | 잘된 일 |
|---|---|
| ① | 원자료의 모든 이슈·리스크·산출물이 들어 있고, 서로 다른 값(예: 진척률 78% vs 80%)이 "확인필요"에 올라감 |
| ② | 서식 순서 그대로, JSON에 없는 숫자·날짜가 0개, null 자리는 "[확인 필요]" |
| ③ | 일부러 심은 오류를 찾아냄 (6장 시험) |
| ⓪ | 담당자가 요청서만 읽고 무엇을 확인할지 1분 안에 앎 |

## 4. 작업 흐름 (누구나 따라 할 수 있게)

1. 담당자: 이번 주 원자료(수행사 보고 메모, 회의 메모, 이슈대장 내용)를 `input.txt`에 붙여 넣기
2. 담당자: `run_team.ps1` 실행 (아래 명령)
3. ① 정리 담당: JSON 작성 → 원자료가 이상하면 **STOP**하고 멈춤
4. ② 작성 담당: 서식대로 초안 작성
5. ③ 검토 담당: JSON과 대조 → **반려**면 문제 목록과 함께 ②로 되돌림 (최대 2회)
6. ⓪ 코디네이터: 검토 요청서 작성
7. 담당자: `4_검토요청서.md` → `최종초안.md` 순서로 읽고 직접 수정
8. 담당자: **결재·발송은 사람이** 기존 절차대로

```powershell
cd C:\LocalAI\pmo-ai-team
powershell -ExecutionPolicy Bypass -File .\run_team.ps1 -InputFile .\input.txt -Date 2026-11-19
```

결과는 `out\날짜_시각\` 폴더에 단계별로 저장됩니다(1_정리.json, 2_초안_r0.md, 3_검토_r0.json, 4_검토요청서.md, 최종초안.md). **팀은 파일을 저장만 하고, 발송·게시·삭제를 하지 않습니다.**

## 5. 도구 (혼자 쓰는 PMO에게 필요한 것만)

| 도구 | 이 팀에서의 역할 | 왜 필요한가 |
|---|---|---|
| **로컬 AI (Gemma 4 26B-A4B + llama.cpp)** | 네 에이전트의 두뇌 | 업무 자료가 폐쇄망 밖으로 나가지 않음 |
| **공유 폴더** (`C:\LocalAI\pmo-ai-team`) | 지식 베이스: 프롬프트, 서식, 용어집, 지난 보고서 | 별도 시스템 없이 버전 관리 가능 |
| **기존 이슈대장 엑셀** | 데이터베이스 | 이미 쓰는 것. 새 도구 도입 불필요 |
| **작업 기록 시트** (엑셀 1장) | 작업 관리 + 측정 | 주차별 소요 시간, 수정 건수 기록 → 효과 증명 |
| **PowerShell 스크립트** (`run_team.ps1`) | 자동화 + 에이전트 간 전달 | 윈도우 기본 탑재, 설치 불필요 |
| **Claude (인터넷 PC)** | 설계자·시험관 | **가상 자료로만** 프롬프트 개선, 실패 사례 분석 |
| 소통 채널 | 해당 없음 | 혼자 쓰고 폐쇄망이라 메신저 연동 불필요 |

## 6. 품질 관리

### 6-1. 검토 지점
| 지점 | 누가 | 무엇을 |
|---|---|---|
| ① 직후 | 스크립트 | STOP 여부, JSON 형식 |
| ③ | 검토 담당 | 숫자·날짜·누락·지어냄·의견 바뀜·과장 |
| ⓪ 이후 | **사람** | 확인 필요 목록 → 본문 → 결재 |

### 6-2. 자주 나올 실패
| 실패 | 막는 장치 |
|---|---|
| 날짜·연도 지어내기 (Nemotron 시험에서 실제 발생) | ① 규칙 4, ② 규칙 1, ③ 날짜오류 검사 |
| 수행사 주장을 PMO 판단처럼 씀 | "수행사 의견:" 표시 유지 규칙 + ③ 의견바뀜 검사 |
| 서로 다른 숫자 중 하나만 고름 | ① 규칙 3 (둘 다 확인필요로) |
| 이슈 누락 | ③ 누락 검사 |
| 검토 담당이 문제를 못 찾음 (로컬 모델 한계) | 사람 검토를 생략하지 않음. 6-3의 함정 시험을 매달 반복 |

### 6-3. 출시 전 사람이 직접 할 시험
1. **지난 3주 보고서 재현:** 지난주 원자료로 돌려서 실제 제출본과 비교
2. **함정 시험:** 원자료에 일부러 서로 다른 진척률, 연도 없는 날짜, 수행사 낙관 의견을 넣고 → ①이 확인필요로 올리는지, ③이 잡는지
3. **빈 자료 시험:** 빈 파일 → STOP 하는지
4. **엉뚱한 자료 시험:** 다른 사업 자료 → STOP 하는지

### 6-4. 효과를 증명할 지표 하나
**주간보고 1건 작성에 드는 담당자 시간(분)**: 도입 전 3주 평균 vs 도입 후 3주 평균.
보조로 "AI 초안에서 사람이 고친 사실 오류 건수"도 기록합니다. 시간은 줄었는데 오류가 늘면 실패입니다.

## 7. 7일 시작 계획 (하루 한 가지)

| 날 | 할 일 | 어디서 | 확인할 것 |
|---|---|---|---|
| **1일** | **기준 측정**: 지난 보고서 작성 시간 기록 + 기관 서식을 `templates`에 옮기기 + 보안 부서에 반입 승인 요청 | 업무 PC | 기준 시간(분) 확보 |
| **2일** | 인터넷 PC에서 반입 파일 준비 (모델, llama.cpp, 이 폴더) + 체크섬 기록 | 인터넷 PC | SHA256 일치 |
| **3일** | 폐쇄망 PC 설치 + 설치 가이드의 시험 6개 | 폐쇄망 PC | 6개 중 5개 이상 |
| **4일** | **① 정리 담당만** 지난주 자료로 시험, 프롬프트 다듬기 | 폐쇄망 PC | 누락 0, 서로 다른 값이 확인필요로 |
| **5일** | **② 작성 + ③ 검토** 추가, 함정 시험 | 폐쇄망 PC | ③이 심은 오류를 잡는지 |
| **6일** | **⓪ 코디네이터** 포함 전체 실행 (`run_team.ps1`), 지난 3주 재현 | 폐쇄망 PC | 사람 수정량, 소요 시간 |
| **7일** | **이번 주 실제 보고서**로 실전 + 시간 측정 + 회고. 통과하면 2주 차에 **회의록 담당** 추가 결정 | 폐쇄망 PC | 기준 대비 시간 단축 |

**위험:** 반입 승인이 7일 안에 안 나올 수 있습니다. 그동안은 인터넷 PC에서 **가상 자료**로 4~6일 차를 미리 해 두면, 승인 후 바로 실전으로 갈 수 있습니다.
